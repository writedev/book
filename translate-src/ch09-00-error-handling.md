# Gestion des erreurs

Les erreurs font partie intégrante du développement logiciel. Rust propose donc plusieurs fonctionnalités pour gérer les situations où quelque chose ne se passe pas comme prévu. Dans bien des cas, Rust vous oblige à reconnaître la possibilité d’une erreur et à prendre des mesures avant que votre code puisse être compilé. Cette exigence rend votre programme plus robuste, car elle vous garantit que vous découvrirez les erreurs et les traiterez correctement avant de déployer votre code en production !

Rust regroupe les erreurs en deux grandes catégories : les erreurs récupérables et les erreurs irrécupérables. En cas d’_erreur récupérable_, comme une erreur _fichier introuvable_, nous souhaitons généralement simplement signaler le problème à l’utilisateur et réessayer l’opération. Les _erreurs irrécupérables_ sont toujours le symptôme de bogues, comme lorsqu’on essaie d’accéder à un emplacement au-delà de la fin d’un tableau ; nous souhaitons donc arrêter immédiatement le programme.

La plupart des langages ne distinguent pas ces deux types d’erreurs et les traitent de la même façon, à l’aide de mécanismes comme les exceptions. Rust n’a pas d’exceptions. À la place, il fournit le type `Result<T, E>` pour les erreurs récupérables, ainsi que la macro `panic!`, qui interrompt l’exécution lorsque le programme rencontre une erreur irrécupérable. Ce chapitre commence par présenter l’appel à `panic!`, puis aborde le renvoi de valeurs `Result<T, E>`. Enfin, nous examinerons les éléments à prendre en compte pour décider s’il faut tenter de récupérer d’une erreur ou interrompre l’exécution.
